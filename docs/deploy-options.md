# カタログを web に出す：検討メモ

2026-09-18（段1の試作を 09-19 に追記）。**デプロイはまだしていない。**
手法の比較と、段1（`out/video-page/`）・段2（`web/`）の試作まで。

出したいもの: エージェント図とデモの案を並べたカタログ（いまの `out/side-catalog/` の形）。
**動画が含まれること**が条件。

---

## 実測したサイズ

| | 実測 |
|---|---|
| 静止画48枚（AgentFlow 全件） | **15MB**（平均 314KB / 1920×1080 PNG） |
| 動画1本（28秒・1920×1080・h264） | **0.5〜1.7MB** |
| 動画を全48本 | **約48MB** |
| 生成される HTML | 31KB |

**動画は思ったより軽い。** 28秒の図なら1本1MB前後で、静止画48枚（15MB）のほうが重い。

---

## 2つの手法

| | Claude Artifact | Cloudflare Pages |
|---|---|---|
| 準備 | **不要** | リポジトリ連携か wrangler |
| 容量 | **64MB / 1バージョン**（バイナリ1ファイル15MBまで） | 実質上限なし |
| 独自ドメイン | 不可 | 可 |
| 公開範囲 | 既定は非公開。共有は後から選べる | 設定する |
| 更新 | 同じURLへ publish し直す | push で自動 |

### 容量に収まるか

- **静止画48枚＋HTML → 余裕**（15MB）
- **静止画＋動画5〜10本 → 収まる**（25MB前後）
- **全48本を動画で → 64MB に迫る。** 動画は選抜する前提になる

**動画が含まれること自体は問題にならない。** `<video>` で普通に再生できる。

---

## 結論（案）

**まず Artifact で出し、足りなくなったら Cloudflare へ移す。**

カタログの HTML は**生成物**なので、置き場を変える追加コストがほぼない。
移り時は「48本すべてを動画で見せたくなったとき」。

### Artifact を選ぶ理由

- セットアップ・アカウント・ドメイン設定が**すべて不要**
- 既定が非公開なので、**社内で見せてから公開を決められる**
- 更新が publish し直すだけ

### Cloudflare を選ぶとき

- 独自ドメインで出したい
- 動画を全件載せたい（64MB を超える）
- リポジトリへの push で自動更新したい

---

## 作るとしたら何を載せるか（案）

- **静止画は全48枚。** 題材ごとに分ける（いまのカタログと同じ見せ方）
- **動画は5本ほど選抜**
  - `Side-DemoFull`（画面が流れる42秒）
  - `Side-Stacked`（上下版）
  - `Side-Replay`（結論から根拠をたどる）
  - `ClaimIntake-SideBySide-Full`（図＋現場＋時計＋反実仮想）
  - `Exhibition-Loop`（展示会ループ）
- 各案に「何を見せるための案か」を1行

## 実装で要ること

いまのカタログは画像を `../agent-flow-gallery/captures-XXX/` で参照している。
**どちらの手法でも、自己完結した1式に組み直す必要がある**（画像を同じ場所へ集める）。

`scripts/side-catalog/build.mjs` に出力モードを足すのが素直。
生成スクリプトが既にあるので、作業はそこだけ。

---

## トークンの目安（作業を頼むときの参考）

**どちらの手法でも、作業の大半は同じ**（カタログを自己完結した1式に組み直す）。
差が出るのは最後の一手だけ。

| | 差分 |
|---|---|
| **Artifact** | 公開の前に**生成された HTML を通しで読む**必要がある（31KB ≒ **約9千トークン**）。画像と動画はパスで渡すので、中身は読まない |
| **Cloudflare** | 生成物を読む必要がない。設定ファイル1つ（wrangler か Actions）を書くだけ。ただし**デプロイの確認に往復が要る**ことがある |

**Artifact のほうが数千トークン多い。** ただし**セットアップの往復が無いぶん、全体では同程度か少ない**可能性が高い。
Cloudflare は初回に認証・プロジェクト作成・DNS などで手が止まりやすく、
そこで人と往復すると簡単に上回る。

**カタログが大きくなるほど Artifact 側の読み取りが増える**ので、
案が100件を超えるような規模になったら Cloudflare のほうが軽くなる。

## 再生速度などの操作も載せられるか（2026-09-18 追記）

Cloudflare へ出す前提なら**載せられる。段は2つある。**

| | 段1：動画を置く | 段2：コンポジションをその場で描く |
|---|---|---|
| 置くもの | mp4 と静止画 | JS バンドル（動画ファイルなし） |
| 速度 | `<video>.playbackRate` | `<Player playbackRate>` |
| シーク | 秒でだいたいの位置へ | **フレーム単位で工程の頭へ正確に** |
| props の差し替え | できない（版ごとに mp4 を作る） | **その場でできる** |
| 追加の実装 | HTML に操作の行を足すだけ | `@remotion/player` を貼る画面を1つ |
| 実測 | 動画1本 0.5〜1.7MB | JS **860KB**（gzip **247KB**）・動画0本 |

**段1は今のカタログの延長。** `<video controls>` に速度のボタンを並べるだけで、
0.5〜4倍は素の HTML でできる。作る手間はほぼゼロ。

**段2は Remotion Studio に近いものが web に乗る。**
`@remotion/player` は既に依存に入っていて（4.0.525）、レンダリングと同じコンポーネントを
ブラウザでそのまま描く。動画ファイルを1本も置かないので、**案を増やしても容量が増えない。**

### 段1の試作（`out/video-page/`）

`pnpm page:video` で組む。**自己完結した1式**なので、フォルダごと上げれば公開できる。

- 動画5本：`ClaimIntake-SideBySide-Full` / `Side-DemoFull` / `Side-Replay` / `Side-Stacked` / `Exhibition-Loop`
- 速度 0.5 / 1 / 1.5 / 2 / 4 倍。**ページ上の全部の動画に同時に効く**
- 一覧の代表画像を `poster` に使う（再生前に何の図か分かる）
- 1本再生すると他は止まる

**実測：動画5本＋代表画像で 7.1MB。** JavaScript は40行ほどで、依存は無い。

一覧（正本）に無い ID の mp4 と、速度違いの mp4 は**ページに載せず、理由を出す**。
書き出したあとに ID を変えると古いファイルが残るので、それが見えるようにしてある。
速度違いを持たなくていいのは、**再生側で速度を変えられるから**。

### 段2の試作（`web/`）

ローカルで動く形まで作った。`pnpm web` で開く（`pnpm web:build` で静的出力）。

- 4件を切り替え：`ClaimIntake-Cards` / `Diagram-Bands` / `ClaimIntake-SideBySide` / `Side-Replay`
- 速度 0.5 / 1 / 1.5 / 2 / 4 倍
- 工程7つへのシーク（`seekTo(step * STEP_LEN)`）
- **props の差し替え**：主体別3帯の題材（原状回復／提案／通報受付）、SideBySide の見せ方プリセット

Vite + `@vitejs/plugin-react`、`@flow/*` → `./src/*` の別名を `tsconfig.json` に追加。
実ブラウザで確認済み（`<video>` 要素は存在せず、コンポジションが生で描かれている）。

ビルド結果は **144 モジュール / 859.94 kB（gzip 246.73 kB）**。

### 段2の気をつけどころ

1. **フォントの読み込みが重い。** 図は CJK フォント（M PLUS Rounded 1c）を使っていて、
   **1ウェイトあたり約120チャンク、3ウェイトで約360リクエスト**になる。
   出すときはサブセット化するか、ウェイトを絞る。
2. **バンドルに全コンポジションが入る。** 48本ぶんのコードと、`shiki` など examples の依存も
   引きずる。Vite も500KB超の警告を出している。出すものだけを読む入口に分けると軽くなる。

### どちらを選ぶか

**まず段1。** 試作した `out/video-page/` がそのまま上げられる形になっている（7.1MB）。
**段2は「その場で条件を変えて見せたい」ときに効く** ——
題材を切り替える、工程の頭へ正確に戻る、といった操作が要るとき。
段1と段2は排他ではないので、カタログ（段1）から個別の案を段2の画面へ送る形にできる。
