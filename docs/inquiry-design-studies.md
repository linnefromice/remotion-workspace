# Inquiry：新しい見せ方の比較

> 現行仕様（全経路の常設）: 全8案で11主体・13接続を常に確認できます。全体図は非アクティブな接続を薄い破線にし、拡大表示の案は全体経路図を常設します。以下の初期案にある「現在の接続だけ」の記述は、末尾の改修で置き換えています。


## 狙いと前提

Iconv2の主体の判別しやすさを残し、商談で「何がどう作用するか」を比較できる3案を作る。
既存と同じ24秒・30fps・1920×1080、6工程。実装済みアプリの画面ではなくInquiry構想の説明。
LINE / Gmailは既存の公式素材、その他は役割ピクトグラムを使う。元のコンポジションは変更しない。

検討した方向は路線図、放射状ネットワーク、受け渡し舞台、担当別スイムレーン、縦の監査記録、等角投影。
担当別レーンと監査記録は説明資料寄り、等角投影は意味のない奥行きが増えるため、今回は前三者を実装する。

| 案 | 主役 | 作用の見せ方 | 確認したい点 |
|---|---|---|---|
| Transit | 全体の経路 | 一つの情報パケットが路線を走る。参照・任意経路は破線 | 明るい画面で分岐と戻りを追えるか |
| Orbit | データと判断の往復 | 中心の判定と周囲の主体を接続、受信側にリング | 線形フローで見えにくい依存関係が伝わるか |
| Relay | その瞬間の受け渡し | 送信側→情報→受信側を大きく提示、工程内でも送り手が交代 | 何が渡ったかを初見で理解できるか |

## 受入条件・実装手順

- 新規フォルダ `src/agent-flow/inquiry/design-studies/` とRootへの追加だけで実装する。
- 既存の11主体・13接続（双方向の判定、業者マスタ参照、任意承認、一次回答、改善）を維持。
- 人は判断基準を調整し、次の判定で参照される。AIを直接書き換える演出にしない。
- 既存と同じく下書き承認の経路を例示し、自動送信の条件や実装を創作しない。
- フレームだけで状態と動作を決定し、参照・非同期・任意の意味を凡例に残す。
- Transit/Orbitは全経路を常設。Relayは全接続を時系列に提示する説明映像で、全体図ではない。
- 型検査→各工程の静止画→動作プレビュー→ギャラリー更新の順で確認。

## 比較の見立て

現時点の推奨は **Transit**。全体経路を保ったまま、明るい会議室でも主体を読み分けやすい。
**Relay** は初見の相手に「具体的に何をしているか」を説明する導入に向く。
**Orbit** はAI判定の往復と改善の環を主張したい場合の案。初見ではTransitより順序を追いにくい。
これらはプロトタイプを見た設計上の判断で、ユーザー検証は未実施。

## 第3追加案: Branches / Terraces

- **Branches**: 暗いチャコールに銅色と青緑の2つの到達先。太い帯は「手配」「回答」の成果のまとまりを示し、実際の13接続は現在の矢印で順に表示する。データ化への判断の返却も維持。下部に人による改善と参照情報を置く。

## レビューで直したこと（2026-09-18）

- **Branches が工程番号で色を決めていた**（`step === 4 ? ... : ...`）。色は主体ごと、という規約に
  正面から反するので、情報の受け手の色を採るようにした。背景の2本の帯は主体ではなく
  「着地のまとまり」なので固定色のままにし、そうとコメントに書いた
- **Chronicle のスクロール量**は指摘を受けたが、**調べたら問題なかった**。
  「padding と下線で実高が131pxになるのに110刻みでスクロールしている」という指摘だったが、
  **Remotion が全体に `box-sizing: border-box` を当てている**ので実高は110のまま。
  変更前後で全フレームがバイト一致することで確認した。
  ただし 110 が3箇所に、上限の 7 が別途書かれていたので、`ROW_H` / `VIEW_H` から導くようにし、
  行にも `box-sizing` を明示して暗黙の前提を消した
- **Terraces の経路が、下へ向かうときも最上段の上まで上がっていた。**
  移動先の段のすぐ上の余白を通すように直した
- **`route()` の orbit 側にフォールバックが無かった。** エッジを1本足すと落ちる状態だった
- **Branches の背景の帯と Lanes のレーン位置が、座標のベタ書きだった。** どちらも POS から
  導くようにした。ふくらみの量など目で合わせた値は、そうと明示して定数にしている
- **圧縮された JSX を Lanes / Terraces でほどいた。** どちらも整形の前後でバイト一致を確認済み

当初は、6案を説明映像として1本だけ描く例外を文書化した。その後のユーザー要望でこの例外を撤回し、以下の全経路常設へ変更した。


## 全経路を破線で残す改修

レビュー指摘を受け、全8案に「現在以外の経路も常時確認できる」を適用した。対象は共有データ `LINKS` の全13接続（11主体）。既存の業務構造や接続を追加・削除していない。

- Transit / Orbit: 既に全接続を描いていた。非アクティブな接続も薄い破線へ統一。
- Lanes / Branches / Terraces: 現在の1本を描く経路関数を全接続で共用。薄い破線を先に描き、現在の経路を最後に重ねる。動く点は現在の経路だけ。
- Relay: 下段の工程カードを全体経路図へ変更。上段の受け渡し拡大表示は維持。
- Chronicle: 右側の詳細に全体経路図を常設。左のスクロールで見えなくなる接続も参照できる。
- Caseboard: 案件カード内に全体経路図を常設。外側の案件への関与の演出を、実際の接続グラフと混同させない。

凡例は「薄い破線＝その他の経路」「強調線と動く点＝現在」で統一。現在の経路が参照・非同期・任意の工程なら、強調線自体も破線を維持する。「薄い破線」を未実装や任意の工程だけとは解釈しない。

`RouteLines.tsx` が13接続の常設と描画順、`RouteOverview.tsx` が拡大表示用の全体図を担う。`pnpm test:inquiry-routes` は実際の8コンポーネントを、各受け渡しの直前・直後と中間フレームで描画し、全13接続のID、現在の1本、非アクティブの破線、座標の有限性を検証する。フレームと画像読み込みだけをテスト用に差し替え、ブラウザでの静止画確認を別途行う。

改修後の検証:
- `pnpm exec tsc --noEmit`、経路常設の8テスト、ギャラリーの3テストが成功。
- 全8案の6工程と改善中の追加フレームをレンダリング。Caseboardの地図下端、Branchesの戻り線・参照線のラベルとの重なりを調整。
- 全8動画を1920×1080 / 30fps / 720フレーム / 24秒 / yuv420pで再出力。レンダリング前後のソースSHA一致。
- 比較ページの56画像・全8動画の読み込みと14秒へのシークが成功。1440px / 390pxで横はみ出しなし。
- AgentFlow全38件の一覧を再生成。対象外30件の中間フレームPNGは前回とバイト一致。
- 書き出しでは12並列・ブラウザ再利用時にページ終了を1回観測。残り6本は4並列・動画ごとの新規ブラウザで完了した。
