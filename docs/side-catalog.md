## 0. 置ける場所と、その広さ

`ClaimIntake-SideBySide` の実測。1920×1080 で図を 0.59倍にして左に置いた場合。

```
┌─ 上（見出し）────────────────────────┬─【右上】─┐
│                                      │  240px   │
├──────────────────────────┬───────────┴──────────┤
│                          │                      │
│   図（1140×641）          │   【右】 590 × 約700  │
│   左に余白なし             │                      │
│                          │                      │
├──────────────────────────┴──────────────────────┤
│  【下】 1808 × 約150（1帯ぶんだけ）                 │
└─────────────────────────────────────────────────┘
```

| 場所 | 広さ | いくつ置けるか |
|---|---|---|
| **右** | 590 × 約700 | 1つ（**ここが本体**） |
| **右上** | 240 × 約120 | 1つ |
| **下** | 1808 × 約150 | **1つだけ**（縦の余地が1帯ぶんしかない） |
| **上** | 見出しの帯 | いまは題名と一文が占めている |
| **左** | **無い** | 図が左端にあるため |

**左に置きたいなら、図を右へ寄せる作り替えが要る。**
上を使いたいなら、題名と場所を分け合うことになる。

---

## 1. 右に置けるもの（本体）

**ここが Side の主役。**「図が語れないこと」を引き受ける場所。

| 要素 | 何を見せるか | 実装 |
|---|---|---|
| **現場** | 工程ごとに、そのとき実際に出ている画面（スマホ / AIのJSON / 発火ルール / 管理画面 / CSV） | `side-by-side/scenes/` の `SCENES` |
| **判断台帳（縦）** | AIの原値・ルールの結論・人の確認を**別の欄に積む**。値が消えないことを形で示す | `Side-Ledger` |
| **判断台帳（組版）** | 同上を Side 専用に組んだ版。通報文を大きく出す | `Side-Evidence` |
| **権限の門** | AI・ルール・人の**3つの門**で、誰が何を決められるかを示す | `Side-Gate` |
| **根拠の逆再生** | **結論から根拠をさかのぼる**。証拠は消さず、注目する場所だけ動く | `Side-Replay` |

> **`Side-*` は「右に置く要素」ではなく、右を主役にした1枚**として作られている。
> 部品として取り出すなら、そこから切り出す作業が要る。

---

## 2. 右上に置けるもの（小さく1つ）

| 要素 | 何を見せるか | 実装 |
|---|---|---|
| **経過時計** | 受付からの経過秒。**速さは図では伝わらない** | `clockSlot` |

差し込み口は `SideSlot`。**新しい要素はここへ差せる**（スキーマを触らなくてよい）。

```ts
const mySlot: SideSlot = {
  claims: ['elapsed'],           // 経過時間を言うなら申告する
  render: ({frame, step, width, showElapsed}) => <...>,
};
```

---

## 3. 下に置けるもの（横長・1つだけ）

| 要素 | 何を見せるか | 実装 |
|---|---|---|
| **反実仮想** | 「その仕組みが無かったら」の結末を2本並べる。**芯が担保なら一番刺さる** | `counterfactualSlot` |
| **追記タイムライン** | イベントが左から積まれる時間軸。**消えないこと**と**待ち時間の在処**を同時に言う | `timelineSlot` |

**排他。** 縦に積める余地が1帯ぶんしかないので、両方は置けない。

---

## 4. まだ無いもの（作るなら）

| 場所 | 案 | なぜ |
|---|---|---|
| 右 | **入力の原文だけ** | いまは工程ごとに切り替わる。1件の通報文を出しっぱなしにする版 |
| 右 | **記録のCSV/JSONだけ** | 出口の形を最初から見せる |
| 右上 | **案件の識別** | 受付番号・受付日時。いまは現場の中に混ざっている |
| 右上 | **工程の進捗** | いまはステップバーが上にある。右上へ移すと上が空く |
| 下 | **凡例と読み方** | いまは図の中の注記。外へ出すと図が軽くなる |
| 下 | **他の題材との対比** | 同じ仕組みが別の業務でも動くことを1行で |
| **上** | **芯の一文** | 「AIが間違えたときどう担保するか」。いまは題名が占めている |
| **左** | — | 図を右へ寄せる作り替えが要る。**費用に見合うかは未検討** |

---

## 5. 選ぶときの決まり

- **右は1つ。** 主役なので、複数置くと何を見ればよいか分からなくなる
- **下は1つ。** 物理的に入らない
- **同じことを2度言わない。** 差し込む要素は「自分が何を言うか」を `claims` で申告し、
  レイアウトが**右上 → 下 → 現場**の順で表示権を1つだけ渡す。
  実際に「47秒」が3箇所に出た事故があり、この仕組みはその再発防止
- **図が既に言っていることは外す。** 左のフロー図が判定の値を出しているなら、
  `mapOnly` でパネルを消す（消さないと右と同じ値を2回言う）
