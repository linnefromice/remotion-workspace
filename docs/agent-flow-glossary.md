# AgentFlow 用語集

図への指示を短く正確にするための対応表。
**この文書の言葉を使えば、どこを指しているか一意に決まる。**

作り方の手順は [`agent-flow-diagram-patterns.md`](./agent-flow-diagram-patterns.md)（[2]）。
ここは「何をなんと呼ぶか」だけ。

---

## 0. 使い方

各表の **「こう言えば伝わる」** が指示の書き方。
用語がコード上の名前と一致しているので、そのまま探して直せる。

> ❌ 「左下の箱をもう少し右に」
> ⭕️ **「担当者ノードを COL_C に寄せて」**

**新しく図を設計するとき**は §1（概念の3軸）から。
**できた図を直すとき**は §2 以降（置き場と見た目）から。

---

## 1. 概念の3軸

**ノードは3つの軸で決まる。** 指示のときは、迷ったらこの3つを言えば一意に決まる。

| 軸 | 問い | 例 | コードに出るか |
|---|---|---|---|
| **主体** | 誰が | AI / ルール / 人 / 記録 | **出る**（`tone` → 色） |
| **作用** | 何をするか | 変換 / 推定 / 強制 / 参照 | 出ない（設計のときだけ使う） |
| **値の役割** | どの値か | 生出力 / 結論 / 確定値 | 出ない（パネルの行に現れる） |

主体だけがコードにあり、**作用と値の役割は図の意味を決めるのに使う**。
新しい図を設計するときは作用から並べ、描くときに主体を色へ落とす。

### 1.1 作用（ノードが何をするか）

4枚の図に繰り返し出てきたもの。**新しいノードを足すときは、まずどれかに当てる。**

| 作用 | 何をする | 例 | ふつうの主体 |
|---|---|---|---|
| **受け口** | 外から非構造を受け取る | 受付 / 立会い / 相談受付 | 入力 |
| **変換** | 非構造 → 構造にする | 文字起こし / 希望の構造化 / 損耗の分類 | AI |
| **推定** | 確率的に値を出す。外しうる | AI判定 / 候補の抽出 / 業務判断 | AI |
| **強制** | 決定論で結論を出す。**AIの値を消さずに別の値を立てる** | セーフティルール / ガイドライン / 規約と現況 | ルール |
| **参照** | 台帳を引く。判断はしない | 業者マスタ / 在庫の入力元 | ルール（灰の線で引く） |
| **判断** | 人が決める。権限を持つ | 担当者 / 営業担当 / 承認ゲート | 人 |
| **出口** | 外に出る成果物 | CSV出力 / 精算書 / 提案一覧 / 一次回答 | 記録 |
| **記録** | 積まれる。消えない | inquiry_events / classifications | 記録 |
| **残置** | 処理から外れたが、消さずに残す | 落ちた候補 | 記録 |

**「残置」は Proposal で初めて必要になった。** 処理から外れたものを消すか残すかは
設計の選択で、残すと決めたならノードとして立てる。

### 1.2 強制の向き

**強制は必ず一方向にしか効かない。** これが図の山場を作る。

| 向き | 何をする | 例 |
|---|---|---|
| **昇格** | 値を強い方へ | 緊急度を P2 → P1 |
| **減額** | 値を弱い方へ | 借主負担を下げる |
| **除外** | 候補を落とす | 成約済みを外す |
| **追加** | 候補を足す | ガードレール G1 が架電を足す |
| **制止** | 先へ進めない | 承認なしに送信しない |

**逆向きができるのは人だけで、理由が要る。** これが「権限の非対称」。
図では、人のノードの説明文に必ず「〜には理由が必要」と書く。

### 1.3 値の役割

山場のパネルの行は、この3つ（＋根拠）で構成する。

| 役割 | 何か | 性質 |
|---|---|---|
| **生出力** | AIが言った値 | **不変。誰にも書き換えられない** |
| **結論** | ルールが出した値 | 生出力を消さずに並ぶ |
| **確定値** | 運用で使う値 | 優先順は **人 > ルール > AI** |
| **根拠** | 確定値がそうなった理由 | ルールIDか、人が書いた理由 |

**上書きのアニメーションを作らない**のは、この4つが同時に存在するから。
消える演出は実装を裏切る。

### 1.4 エッジの種類

| 種類 | 何を運ぶ | 見た目 |
|---|---|---|
| **受け渡し** | 処理が次へ進む | 実線・系統色 |
| **参照** | 引くだけ。流れではない | 灰の実線 |
| **差し戻し** | 人が前の工程へ戻す | 人の色・遅延つき |
| **通らない経路** | 未実装、または今回は条件が合わない | 破線・非点灯 |

## 2. 図の骨格

```
        ┌── 外側 ──┬────────── ランタイム枠 ──────────┐   ┌ 記録層 ┐
OUTSIDE │ ▢ 退去者  │  ROW_1   ▢     ▢     ▢     ▢    │   │ ▭ チップ│
  _CX   │          │  ROW_2   ▢     ▢     ▢     ▢    │   │ ▭ チップ│
        └──────────┴─────────COL_A COL_B COL_C COL_D─┘   └────────┘
                       ▢ 担当者        ▢ 出口
                       （枠の下）
```

| 用語 | 指すもの | コード | こう言えば伝わる |
|---|---|---|---|
| **ランタイム枠**（枠） | 実装の責任範囲を囲む角丸の矩形 | `spec.frame` | 「枠を下に80px広げて」 |
| **外側** | 枠の外にいる登場人物。入居者、候補者、業者 | `OUTSIDE_CX` | 「施工業者は外側へ出して」 |
| **記録層** | 右端に縦に並ぶ小さなチップの列 | `REC_CX` / `recordHeader` | 「記録層にチップを1枚足して」 |
| **行**（ROW） | ノードの縦位置。`ROW_1` が主系列、`ROW_2` が分岐や落ちたもの | `ROW_1` `ROW_2` | 「ROW_2 に置いて」 |
| **列**（COL） | ノードの横位置。左から `COL_A`〜`COL_D` | `COL_A`…`COL_D` | 「COL_C に寄せて」 |
| **主系列** | ROW_1 を左から右へ一直線に読める並び | — | 「主系列が折れているので直して」 |
| **すきま**（GAP） | 列と列、行と行のあいだ。線を通すために使う | `GAP_X` `GAP_Y` | 「GAP_X を通して降ろして」 |
| **車線**（レーン） | 枠の外で線を横に走らせる決まった高さ | `LANE_Y` `SETTLE_LANE` | 「車線を40px下げて」 |

**寸法**: ノードは `NODE_W`(208) × `NODE_H`(116)、記録チップは `REC_W`(208) × `REC_H`(62)。
行の中心距離は **280px**（一番背の高い LogoSeal 版が収まる最小）。

## 3. ノード

| 用語 | 指すもの | コード | こう言えば伝わる |
|---|---|---|---|
| **ノード** | 図の箱ひとつ。工程か登場人物 | `NodeDef` | 「ノードを1つ足して」 |
| **カード** | Cards 版でのノードの見た目（箱＋説明文） | — | 「カードの説明文を短く」 |
| **記録チップ** | 記録層の小さな箱。アイコンを持たない | `record: true` | 「記録チップにして」 |
| **平箱** | 版を切り替えても箱のままにするノード | `plain: true` | 「入力元は平箱のままで」 |
| **トーン** | ノードの主体（色が決まる） | `tone` | 「トーンを rule にして」 |
| **点灯** | いまの工程でノードや線が光っている状態 | `active` / `steps` | 「工程5でも点灯させて」 |
| **破線ノード** | 任意の入力、または通らない工程 | `dashed: true` | 「破線にして」 |
| **見出し** | ノードの日本語名（大きい文字） | `jp` | 「見出しを短く」 |
| **英字ラベル** | ノード上部の小さな英字 | `en` | 「英字ラベルを直して」 |
| **説明文** | Cards 版で見出しの下に出る文 | `desc` | 「説明文を1行に」 |
| **動作** | LogoSeal / ActionRow 版で出す短い言い切り | `action` | 「動作を『所見を残す』に」 |
| **アイコン** | ノードの絵文字ではなくピクトグラム | `icon` | 「アイコンを check に」 |

**トーンの一覧**: `input` / `ai` / `rule` / `human` / `record` / `planned`

**アイコンの一覧**（これ以外は使えない）:
`phone` `wave` `calendar` `check` `people` `agent` `database` `branch` `tool` `message` `inbox` `sliders`

## 4. エッジ（線）

| 用語 | 指すもの | コード | こう言えば伝わる |
|---|---|---|---|
| **エッジ** | ノードをつなぐ線 | `EdgeDef` | 「エッジを1本足して」 |
| **経由点** | 線が曲がる点の配列。ここから経路が決まる | `points` | 「経由点を1つ足して回り込ませて」 |
| **直角ルーティング** | 斜めに引かず、縦横と角丸だけで引く方式 | `roundedPath` | 「直角で引いて」 |
| **ポート** | 線がつながるノードの辺の中点 | `left()` `right()` `top()` `bottom()` | 「右ポートから出して」 |
| **遅延** | 同じ工程の2本目以降を遅らせて光らせる | `delay` | 「遅延を45フレームに」 |
| **通らない経路** | 未実装、または今回は条件が合わない線 | `step: null` | 「通らない経路として残して」 |
| **参照線** | 流れではなく参照であることを示す灰色の線 | `color: COLORS.grey` | 「参照線にして」 |
| **線のラベル** | 線の中点に置く短い注記 | `label` | 「ラベルを『任意』に」 |
| **走る点** | 点灯中の線を進む丸 | — | 「走る点を消して」 |

## 5. 時間と点灯

| 用語 | 指すもの | コード | こう言えば伝わる |
|---|---|---|---|
| **工程**（ステップ） | 図の進行の単位。1工程 = 4秒 = 120フレーム | `STEPS` / `STEP_LEN` | 「工程を1つ足して」 |
| **工程番号** | 0始まり。表示は `+1` して 01〜07 | `step` | 「工程3（表示は04）から」 |
| **尺** | 図全体の長さ。7工程で28秒 = 840フレーム | `TOTAL_FRAMES` | 「尺を24秒に」 |
| **局所フレーム** | いまの工程に入ってからの経過フレーム | `localFrame` | 「局所フレーム30から出して」 |
| **立ち上がり** | 点灯が0から1になるまでの短い時間 | `rampIn` | 「立ち上がりを遅く」 |
| **工程色** | ステップバーと進捗バーに使う色の並び | `stepColors` | 「工程4の色を白に」 |

**ノードの色は工程色ではなくトーンで決まる。** 工程色はバーだけに使う。

## 7. 色と主体

色は**工程ではなく主体**に割り当てる。

| 主体 | 色 | トーン | 意味 |
|---|---|---|---|
| 入力 | シアン `#22D3EE` | `input` | 外から来るもの |
| AIの推論 | 紫 `#8B5CF6` | `ai` | 確率的なもの |
| **決定論のルール** | **白 `#FFFFFF`** | `rule` | **AIでも人でもない第3の主体。色相を持たせない** |
| 人の判断 | オレンジ `#FF6B1A` | `human` | 介在 |
| 記録 | 緑 `#34D399` | `record` | 積まれるもの |
| 通らない経路 | 灰 `#4A5769` | `planned` | 未実装・条件外 |

## 8. 版（4つ・規定）

| 版 | 見た目 | 中心から上／下 | こう言えば伝わる |
|---|---|---|---|
| **Cards** | 箱＋説明文 | 58 / 58 | 「Cards 版で」 |
| **LogoSeal** | 円の中にアイコン、下にラベル | 64 / **164** | 「LogoSeal 版で」 |
| **IconsV2** | LogoSeal ＋ 実ロゴ | 64 / 164 | 「IconsV2 で LINE を出して」 |
| **ActionRow** | 箱＋短い動作1行 | 52 / 110 | 「ActionRow 版で」 |

- `variant` は `cards` / `logoSeal` / `actionRow`。**IconsV2 は `logoSeal` + `brandIcons`**
- **`Icons`（ピクトグラム版）は ClaimIntake / Inquiry にしかない別物。** 規定の4版には入らない
- 実ロゴを出せるのは `line` と `gmailLine` だけ（`spec.brands`）

## 12. 紛らわしい言葉

**実際に取り違えが起きたもの。** 左の言い方は避ける。

| 避ける | なぜ | こう言う |
|---|---|---|
| 「ステップ」 | 工程かフレームか曖昧 | **工程** |
| 「箱」「ボックス」 | カード / 記録チップ / 平箱の3つがある | **ノード** または **記録チップ** |
| 「パネル」 | 山場のパネルと、1枚もの側の現場パネルがある | **山場のパネル** |
| 「アイコン版」 | `Icons`（ピクトグラム）と `IconsV2`（実ロゴ）は別物 | **IconsV2** |
| 「P1」「P2」 | **緊急度**を指す語。他の番号付けに使わない | 依頼書なら「洗い出し／深掘り／粗探し」 |
| 「色を変えて」 | 工程色とトーンのどちらか分からない | **トーンを◯◯に** / **工程◯の色を** |
| 「行」 | ROW_1/ROW_2 か、パネルの行か | **ROW_2** / **パネルの行** |
| 「上に出して」 | 枠の上か、画面の上か | **枠の外の上** / **画面上部** |
| 「ルールのノード」 | 主体（トーン）か作用（強制）か | **トーンが rule** / **強制のノード** |
| 「値」 | 生出力・結論・確定値のどれか | **生出力** / **ルールの結論** / **確定値** |

## 13. 指示の例

```
Restoration の ROW_2 に「特約の確認」ノードを足して。
トーンは rule、アイコンは check、破線で。工程3で点灯。

Proposal-LogoSeal で「落ちた候補」の見出しが下の行に被っている。
行の中心距離を広げて。

山場のパネルに「差引」の行を足して、出現工程は4、強調行にして。

ClaimIntake の担当者から記録層への線が精算書を横切っている。
車線を通して回り込ませて。

Restoration を IconsV2 でも出したい。見積の受領に gmailLine を割り当てて。
```

設計のとき（§1 の言葉で）:

```
この工程は「参照」で、判断はしない。灰の線で引いて。

ここに「強制」を1つ足したい。向きは除外。落ちたものは残置で残す。

パネルは生出力・結論・確定値の3行。根拠はルールIDを注記に。
```
