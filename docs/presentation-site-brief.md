# プロトタイピング依頼：デモを想像させる1枚の見せ物

このファイルだけ読めば着手できるように書いてあります。
**設計から任せます。** 以下は解くべき問題と前提であって、仕様書ではありません。
ここに書いていない見せ方を思いついたら、そちらを優先してください。

自分の案を出してから読むことをすすめます。

## 1. 解きたい問題

賃貸物件の通報受付エージェント（PoC・実装済み）を、商談や展示会で見せたい。
手元には**エージェントの処理フローを図解した28秒の動画**がある。

問題は、フロー図だけでは肝心のことが伝わらないこと。

| フロー図が語れること | 語れないこと |
|---|---|
| どこからどこへ流れるか | 当事者が何を見ているか |
| どの工程に人が挟まるか | その工程が何秒かかるか |
| ルールが緊急度を上げること | **上げなかった場合に何が起きるか** |

商談で本当に聞かれるのは「AIは正確ですか」ではなく
**「AIが間違えたとき、どう担保するんですか」**です。最後の行がそこに重なっています。

**この動画に何を足せば、見た人が「実際に動いているところ」を想像できるか。**
それを考えて、プロトタイプまで作ってください。

### 決まっていないこと

- 最終形が動画1本なのか、動画を埋めたHTMLの1枚サイトなのか。
  触って試せる要素を入れるならサイトになりますが、**そこも含めて提案してかまいません**
- 情報量を増やすと視線が散ります。何を主役にして、何を従に倒すか

## 2. 題材の中身

作り込むなら、この PoC が何を主張しているかを知っている必要があります。
実装は `farleap/tenant-claim-intake-demoapp`（このリポジトリの外）にあります。

### シナリオ（既存の図が使っているもの）

入居者が「キッチンの下から水が漏れています。ガスのようなにおいも少しします」と
写真つきで通報する。AIは **P2（翌営業日）** と判定する。
しかし「ガスのようなにおい」に反応して安全ルール `SAFETY_GAS_ODOR` が発火し、
**P1（即時）** へ引き上げる。担当者が確認し、受付から47秒で一次回答が返る。

### 設計上の主張（ここが商材の芯）

1. **判定の非対称**。緊急度の**昇格は決定論のルールが強制**し（5本）、
   **降格は人だけ**ができて理由の入力が要る。AIには降格の権限が無い
2. **AIの出力を書き換えない**。AIの生出力（P2）はそのまま保存され、
   ルールの結論（P1）は別の値として乗る。**両方が残る**。
   だから「なぜP1だったのか」を後から1行で追える
3. **痕跡が消えない**。イベント記録は追記のみで、更新と削除の経路が実装に無い
4. **2段階の判定**。1段目が緊急度とカテゴリ、2段目が責任区分と次の対応候補。
   2段目にはガードレールが5本あるが、**できるのは候補の追加と制止だけ**で、
   候補を削る経路は無い

**「AIが判定します」ではなく「AIが外したときに効く仕掛けが入っています」が売り。**
見せ物もそこに寄せてください。

## 3. 環境と、守ってほしいこと

Remotion v4 のワークスペースです。`pnpm dev` で Studio が開きます。

```
pnpm dev                                   # Studio
pnpm exec remotion compositions            # 一覧
pnpm exec remotion still <Id> out.png --frame=420 --gl=swangle
pnpm exec remotion render <Id> out.mp4 --gl=swangle --image-format=png --pixel-format=yuv420p
pnpm exec tsc --noEmit
```

### 動画側の約束ごと

- 1920x1080 / 30fps / 840フレーム。**120フレーム（4秒）ずつ7ステップ**
- 状態は `useCurrentFrame()` だけから決める。乱数や時刻を使わない
- **既存のコンポジションの出力を変えない**。手を入れるなら、既定でこれまでどおりに
  なるフラグを足す形にする（実例は §6）

### 図の作法（守る価値があるもの）

これまでの検証で効いた判断です。詳しくは [`agent-flow-verification.md`](./agent-flow-verification.md) §6。

- **座標を2箇所に書かない**。ノード位置とエッジの経由点を同じグリッド定数から導く
- **通らない経路を消さない**。未実装の経路も、条件が合わず今回通らない工程も、
  破線で残す。実装にあるものを図から消すと図が嘘になる
- **決定論のルールに色相を与えない**。AIでも人でもない第3の主体は白で立てている。
  これは題材のアプリ自身の判断を借りたもの
- **上書きのアニメーションを作らない**。ルールがAIの値を書き換える演出は、
  実装が「書き換えない」設計である以上、嘘になる

### 出力を変えていないことの示し方

このリポジトリでは、リファクタや機能追加のときに
**同じフレームのPNGを `cmp` でバイト比較**して見た目が変わっていないことを示しています。

```sh
pnpm exec remotion still <Id> before.png --frame=420 --gl=swangle
# ...変更...
pnpm exec remotion still <Id> after.png --frame=420 --gl=swangle
cmp before.png after.png
```

一度、**レンダー実行中にソースを書き換えてしまって偽の差分を出した**ことがあります。
以降はレンダーの前後で `md5` を取り、実行中に変化していないことも併せて確認しています。

## 4. 環境で踏んだ罠

自分で踏み直さなくていいように。全部 [`agent-flow-verification.md`](./agent-flow-verification.md) §4 にあります。

| 事象 | 対処 |
|---|---|
| headless Chromium が WebGL コンテキスト生成に失敗する | `--gl=swangle`（`--gl=angle` では不十分） |
| 動画の pix_fmt が `yuvj420p` になる | `--image-format=png` と `--pixel-format=yuv420p` を**両方**指定する |
| `zod` はメジャーではなく exact 一致が要求される | 触らない。`npx remotion versions` で確認 |
| 親要素に CSS `opacity` を掛けると背後のSVGが透ける | 背景と枠は不透明のまま、中身だけ内側の wrapper で掛ける |
| `position: absolute` の部品を絶対配置ラッパーで囲むとオフセットが二重になる | 逆オフセットで打ち消すか、同じ座標系の `relative` の帯を使う |
| 日本語がカード幅に対して1文字だけ次行に落ちる | 幅と字数を手で合わせている。自動では解けていない |

## 5. 進め方

- 案は**別コンポジションとして足す**。既存には触らない
- 見せ方の切り替えは `zod` スキーマ＋`defaultProps` にすると、
  Studio の props パネルから組み合わせを試せます（`CLAUDE.md` にパターンあり）
- 各ステップの中間フレーム（60, 180, 300, 420, 540, 660, 780）を静止画で書き出して
  目視するのが、いちばん速い確認方法です
- 考えたことは [`presentation-site.md`](./presentation-site.md) に追記してください。
  このリポジトリでは設計メモを更新しながら進める運用にしています

## 6. 補足：既に試した分（Claude が作ったもの）

**§1 で自分の案を出してから読んでください。**

Studio の `AgentFlow > ClaimIntake > ClaimIntake-SideBySide*` にあります。
実装は `src/ClaimIntakeSideBySide/`、検討の経緯は [`presentation-site.md`](./presentation-site.md)。

### 土台の発想：同じ瞬間を「俯瞰」と「現場」で同時に見せる

フロー動画を縮小して左に置き、右に**そのステップで実際に出ている画面**を並べました。

| ステップ | 右に出しているもの |
|---|---|
| 受付 | 入居者のスマホ（LINEのトーク画面） |
| 文字起こし | 音声の波形と、起こされたテキスト |
| AI判定 | **AIの生出力そのもの** `{"urgency":"P2","confidence":"medium"}` |
| ルール昇格 | 発火した `SAFETY_GAS_ODOR` と、書き換わらず並ぶ2つの値 |
| 業務判断 | NextAction候補（ガードレールが足したものに印） |
| 人の確認 | 担当者の管理画面（P1バッジ・「降格には理由が必要」） |
| 出口 | CSVの1行（`urgency_ai` と `fired_rule_ids` が並ぶ） |

狙いは1つだけです。**「AIがP2と言った」は抽象だが、JSONに `"P2"` と書いてあるのを
見せると現実になる。**

実装上のコツ：既存のコンポジションを `transform: scale()` で縮めて埋めるだけで、
中身は `useCurrentFrame()` から状態を決めているので**同期のコードが要りません**。

### 足したもの（`SIDE_BY_SIDE_PRESETS` で切り替え）

| プリセット | 何を足したか | どうだったか |
|---|---|---|
| `plain` | 何も足さない | 成立した。0.59倍に縮めてもノード名は読める |
| `map` | 埋め込むフロー図から判定パネルを外す（`hidePanel`） | 左右で同じ値を2回言う重複が消えた。代わりに図の左下が空く |
| `counterfactual` | 下段に、ルールの有無で結末が変わることを置く | §1の表の「語れないこと」に直接当たる。空き地にちょうど収まった |
| `full` | `map` + `counterfactual` + 経過時計 | いまのところこれが一番よい |
| `timeline` | 下段を、イベントが左から積まれる時間軸にする | 追記のみ（消えない）と、速さを1つの帯で言える |

### やってみてわかったこと

1. **縮小しても読める**。事前には「地図用の簡略版が要る」と思っていましたが、不要でした
2. **1920x1080 に縦へ積める余地は、下に1帯ぶんしかない**。
   `counterfactual` と `timeline` は場所を取り合うので**排他**にしてあります。
   両方見せたいなら、キャンバスを変えるか、時間で切り替えるか、サイトにするかです
3. **同じ数字を3箇所で言ってしまいがち**。「47秒」が時計・現場・反実仮想で重複し、
   フラグで抑制しました。**足すたびに、既にどこかで言っていないか**を確認してください

### 手つかずのまま残っていること

1. **触って試せる要素**。定型文を3つほどから選ぶと発火するルールが変わる、程度のもの。
   「説明された」が「試した」に変わるはずですが、**動画では作れません**
2. **降格のシナリオ**。判定の非対称の片側（ルールによる昇格）しか描けていません。
   AIがP1と言い、人が理由を書いて下げる側を見せると、主張が両側そろいます
3. **元の図のラベル重なり**。`ClaimIntake-IconsV2` の LINE ノードで
   「Webhook / 外部チャネル」の折り返しが下のタグに被っています。未修正です
