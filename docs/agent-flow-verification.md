# AgentFlow 実装検証まとめ

Remotion で「エージェントが動いている風のフロー図」を作れるか、という検証の記録。
2026-09-16 から 2026-09-17 にかけて、図を4題材ぶん作りながら Remotion の実用性を測った。

個別の設計は [`agent-flow-inquiry.md`](./agent-flow-inquiry.md) と
[`agent-flow-claim-intake.md`](./agent-flow-claim-intake.md) にある。ここは横断のまとめ。

## 1. 結論

**Remotion はこの用途に向いている。** 決め手は3つ。

1. **フレーム番号の純関数として書ける**。`useCurrentFrame()` だけで状態が決まるので、同じフレームは何度描いても同じ絵になる。シークとレンダリングが一致し、途中のフレームだけ書き出して目視確認できる
2. **図をデータとして持てる**。ノードとエッジを配列で持ち、座標をグリッドから導出すれば、見た目の修正がコードの修正で済む。デザインツールでの作り直しが要らない
3. **差分の検証ができる**。書き出した PNG を `cmp` でバイト比較すれば、リファクタで見た目が変わっていないことを機械的に証明できる（§5）

弱点は**レイアウトの試行錯誤が遅い**こと。ブラウザの devtools のように直接いじれないので、
数値を直してレンダーして目視、を繰り返す。1枚あたり2〜4秒かかるので、詰めの調整は回数が効く。

## 2. 作ったもの

| 題材 | 尺 | ステップ | 何を伝える図か |
|---|---|---|---|
| **ClaimIntake** | 28秒 | 7 | 実装済み PoC（`farleap/tenant-claim-intake-demoapp`）の構造。AI・ルール・人の権限の非対称 |
| **Inquiry** | 24秒 | 6 | 問い合わせ対応フローの構想。ルールと文脈を人が育てる改善サイクル |
| **Reference** | 20秒 | 4 | Cloudflare 音声エージェント参照図の再現と、その保守性リファクタ版 |
| **Exhibition** | 20秒 | 5 | 展示会で流すシームレスループ |

ClaimIntake と Inquiry は、ノードの描き方だけを変えた4版（`Cards` / `Icons` / `LogoSeal` / `ActionRow`）がある。
構造・タイムライン・判定パネルは共有していて、差分は見せ方だけに閉じている。

行数はフロー図の合計で約4,300行（部品カタログと共有部品を含む）。

## 3. 測定値

Apple M5 Max（18コア）/ Concurrency 8x での実測。

| 題材 | フレーム数 | render | mp4 |
|---|---|---|---|
| Exhibition-Loop | 600 | 約10〜12秒 | 515 KB |
| Reference-Cloudflare-Refactored | 600 | 約12〜15秒 | 752 KB |
| Inquiry-Cards | 720 | 約12秒 | 605 KB |
| ClaimIntake-Cards | 840 | 約17秒 | 855 KB |

静止画は1枚あたり約2〜3秒。いずれも 1920x1080 / 30fps / H.264 / yuv420p。

**グローと波形の負荷は無視できる**。有効・無効で比較レンダーしたところ、有効時 約13.6〜14.8秒 /
無効時 約12.9〜13.6秒で、1割前後の差にとどまった。`box-shadow` の CSS グローと SVG の
`feGaussianBlur` を、常に1つのノードとエッジにしか掛けない設計にしたため。

## 4. Remotion 固有でつまずいた点

実装中に実際に踏んだものだけを挙げる。

| # | 事象 | 対処 |
|---|---|---|
| 1 | `zod` はメジャーではなく **exact バージョン一致**が要求される。`remotion@4.0.525` は `zod@4.5.4` を要求し、`^4.6.5` を入れるとレンダリングが Version mismatch で止まる | `npx remotion versions` で要求版を確認して固定 |
| 2 | `@react-three/fiber@9.7.0` の peer 制約（`react "<19.3"`）は**本当に壊れる**。`react@19.3.0` だと `remotion render ThreeScene` が `commitLayoutEffectOnFiber` で例外 | `react` / `react-dom` を `19.2.8` に固定 |
| 3 | headless Chromium が素の WebGL コンテキスト生成に失敗する（このマシン） | `--gl=swangle` を付ける。`--gl=angle` では不十分だった |
| 4 | CJK フォントを `@remotion/google-fonts` 経由で読むと、1ウェイトあたり約120チャンクに分割され、3ウェイトで約360リクエストになる | 実害は軽微。`ignoreTooManyRequestsWarning: true` で警告を抑える |
| 5 | `Config.setVideoImageFormat("jpeg")` のままだと `yuvj420p`（フルレンジ）になる。`--pixel-format=yuv420p` 単体では効かない | その回だけ `--image-format=png --pixel-format=yuv420p` を明示する |
| 6 | CSS `opacity` を親要素に掛けると、背後の SVG レイヤーが透けてグリッドや線がカード越しに見える | 背景と枠は不透明のまま残し、中身のテキストだけ内側の wrapper で `opacity` を掛ける |
| 7 | `position: absolute` を内部に持つ部品を、別の絶対配置ラッパーで囲むと**オフセットが二重**になる | 打ち消し用の逆オフセット、または同じ座標系の幅を持つ `position: relative` の帯を用意する |

5番と6番は「動いてはいるが仕様と違う」類なので、目視だけでは気づきにくい。
5番は `ffprobe` で、6番はキャプチャの拡大で見つけた。

## 5. 出力を保ったままリファクタできるか

`AgentFlowCodex`（Codex 生成）を読みやすく書き直した `AgentFlowCodexReClaude` で試した。

- **座標の重複を解消**: 元は7ノードの `x/y/w/h` と各エッジの SVG パス文字列（`'M380 306 H575'` など）が
  別々のリテラルだった。ノードを動かすとエッジ側を手で直す必要があり、直し漏れがそのまま
  「線がノードからズレる」バグになる。列と行のグリッドから両方を導出する形に変えた
- **手描き曲線の解読**: コーナー半径とレーン座標を1つずつ検算して名前付き定数に分解した。
  グリッドに沿わない値（目視で決め打ちされた座標）は、そうと正直にコメントし、
  **存在しない規則性を捏造しなかった**
- **検証**: frame 0/1/40/75/149/150/220/299/300/450/500/599（各ステップ境界と delay 境界を含む）で
  両方を書き出し、`cmp` で **PNG がバイト単位で完全一致**することを確認した

つまり **Remotion では「見た目を1ピクセルも変えずに内部構造だけ直す」が機械的に保証できる**。
これは映像制作ツールでは普通できないので、コードで図を持つ最大の利点だと思う。

## 6. 設計で効いたこと

図を何枚か作ってわかった、再利用できる判断。

- **座標を2箇所に書かない**。ノードの位置とエッジの経由点を同じグリッド定数から導出する。
  これを最初からやった Inquiry 以降は、ノードサイズを何度変えてもエッジ側を触らずに済んだ
- **直角ルーティング**。経由点の配列を持たせ、角丸の折れ線として描く。斜めのベジェ曲線は
  ノードの枠や文字を横切りやすい
- **「通らない経路」を描く**。未実装（LINE webhook）と、条件が合わず今回は通らない工程
  （P1 では聞かない追加質問）を、破線・非アクティブのまま置く。
  実装にあるものを図から消すと、図が嘘になる
- **決定論のルールに色相を与えない**。ClaimIntake では、AI でも人でもない第3の主体を
  白（無彩色・最強コントラスト）で立てた。題材のアプリ自身の設計判断を借りている
- **上書きのアニメーションを作らない**。AI の出力をルールが書き換える演出は、実装が
  「書き換えない」設計である以上、嘘になる。2つの値を並べて片方に印を付ける形にした

## 7. 残っている課題

1. **レイアウトの試行錯誤が遅い**。Studio のプレビューは速いが、詰めの微調整は
   数値を変える → 書き出す → 見る、の往復になる
2. **共有部品の置き場**。エッジ描画のロジックが `AgentFlowInquiry` と `AgentFlowClaimIntake` に
   同じ内容で2つある。3枚目を作るときに `src/shared/` へ寄せる
3. **日本語の改行制御**。カード幅に対して文字数が多いと1文字だけ次行に落ちる。
   現状は幅と字数を手で合わせている
