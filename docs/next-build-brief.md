## 0. 何のための作業か

賃貸管理のエージェントを、商談と展示会で見せるための素材を作っている。
図は41本あり、そこから**採用するものを絞る段階**に入った。

採用候補のうち **Side（図の横に何を置くか）** の3件が、この依頼の範囲。

| | 何を作るか | 大きさ |
|---|---|---|
| **A** | SideBySide に**時計だけ**足した版を登録する | 小 |
| **B** | SideBySide の**右上と下部を差し込み式**にする | 中 |
| **C** | **デモ画面がフルで流れる**ものを作る | 大・設計から |

**A → B → C の順**。A は B の下ごしらえになり、B ができると C の置き場が決まる。

## 1. いまある形

`ClaimIntake-SideBySide` 系は、1つのコンポーネントを props で切り替えている。

```
src/agent-flow/claim-intake/side-by-side/
  index.tsx                   レイアウト本体
  constants.ts                寸法・zodスキーマ・プリセット
  scenario.ts                 この1件の事実（受付番号・AIの値・ルールID・経過秒）
  parts/primitives.tsx        小部品
  scenes/index.tsx            工程ごとの「現場」7枚と、それを並べた SCENES
  panels/Counterfactual.tsx   下段の帯（反実仮想）
  panels/EventTimeline.tsx    下段の帯（追記タイムライン）と経過時計
```

```
┌──────────────┬──────────┐
│              │ 【右上】  │  clock
│   フロー図     ├──────────┤
│  （縮小埋込）   │  現場     │  SCENES［7工程］
└──────────────┴──────────┘
  【下部】                    counterfactual または timeline
```

スキーマは `mapOnly` / `counterfactual` / `timeline` / `clock` の**真偽値4つ**。
プリセットは `plain` / `map` / `counterfactual` / `full` / `timeline` の5つ。

## 2. A：時計だけ足した版を登録する

### 作るもの

`{ mapOnly: ?, counterfactual: false, timeline: false, clock: true }` のプリセットと、
それを使うコンポジション。**この組み合わせは今どのプリセットにも無い**
（props パネルからは作れる）。

### 決めること

- **`mapOnly` を併せるか。** 併せないと、左のフロー図が持つ「判定の非対称」パネルと
  右の工程4が**同じ値（AI P2 / ルール P1）を2回言う**。
  併せると左下が空く。撮って見て決める
- **ID。** 題材フォルダに置くので `<題材>-<名前>`（[`presentation-site-variants.md`](./presentation-site-variants.md) の ID の決まり）。
  `ClaimIntake-SideBySide-Clock` を想定しているが、これが規定になる予定なので名前は相談したい

### 終わったと言える条件

- `pnpm exec tsc --noEmit` が通る
- 各工程の中間フレーム（60, 180, 300, 420, 540, 660, 780）を撮って目視
- **既存の5本（`SideBySide` / `-Map` / `-Counterfactual` / `-Full` / `-Timeline`）の出力が変わっていない**ことを
  `cmp` のバイト一致で示す（§5）
- `pnpm gallery:agent-flow` で一覧を作り直す（§5）
- `pnpm test` が通る

---

## 3. B：右上と下部を差し込み式にする

### なぜ

**題材ごとに、右上と下部へ独自の要素を足せるようにしたい。**
いまは「用意した4つのフラグから選ぶ」形で、新しい要素を足すたびに
スキーマとレイアウトの両方を触ることになる。

### 引き継ぐ制約（実測。守らないと破綻する）

- **下部に置けるのは1つだけ。** 1920×1080 に左右2カラムを置くと、
  縦に積める余地が**1帯ぶん（約110〜150px）しかない**。
  だから反実仮想と時間軸は排他にしてある
- **右上も1つだけ。** ヘッダの右は時計1つでちょうどの幅
- **現場（右の本体）は差し替えの対象外。** ここが SideBySide の主役

### いちばん考えてほしいところ

**同じことを2度言う事故を、誰が防ぐか。**

過去に「47秒」が**時計・現場の出口・反実仮想の3箇所**に出た。
いまは `hideElapsed` で**レイアウトが知っていて抑えている**
（`index.tsx` が `clock || timeline` を見て現場に渡している）。

差し込み式にすると、**差し込む側は他に何が出ているか知らない**。
この判断をどこに持たせるかを決めてほしい。案は3つ思いつくが、どれでもよい。

1. 差し込む要素が「自分は経過時間を言う」と申告し、レイアウトが重複を落とす
2. レイアウトが引き続き判断する（＝スロットの種類を型で縛る）
3. 防がない。代わりに**テストで重複を落とす**（下の §5 の作り方が使える）

### 終わったと言える条件

- 既存の5本 ＋ A で作った版の**出力がすべて変わっていない**（バイト一致）
- 新しい要素を1つ、差し込みで足して見せられる（既存のどれかを移植でよい）
- 「同じことを2度言わない」仕組みが何であるかを、コードかドキュメントで説明できる

## 4. C：デモ画面がフルで流れるもの

**まだ何も無い。設計から。** 既存はすべて「図の横に画面を添える」形で、
画面そのものが主役になって流れるものは作っていない。

### 先に決めること

1. **どこまで作るか。** 実アプリの画面を再現するのか、説明用に組み直すのか。
   **既存の Side 系はすべて「説明用の画面再構成 / 実システムへの接続なし」と
   画面に明記している。** 同じ線を引くのか、実物を録るのかで別物になる
2. **尺と工程。** いまは28秒に7工程（1工程4秒）。画面を流すなら1画面4秒は短いかもしれない
3. **操作の見せ方。** クリックやスクロールを描くのか、画面の切り替えだけにするのか
4. **図をどこに置くか。** 出さない／小さく地図として置く／最初と最後だけ出す

### 素材はどこにあるか

**`scenario.ts` の `CASE` と `EVENTS` が、この1件の事実の正本。**
受付番号・AIの値・ルールID・イベントの時刻がここにある。
画面に出す値は**ここから引く**（2箇所に書かない）。

工程ごとの画面の中身は `scenes/index.tsx` に7枚ある
（スマホ / 文字起こし / AIのJSON / 発火ルール / NextAction / 管理画面 / CSV）。
**フル版はこれを拡張したものになるはず**なので、まず読んでほしい。

### 置き場

`AgentFlow > DesignStudies > Side`（ID は `Side-<名前>`）。
図の横ではなく図の代わりだが、比べる相手は Side の候補と同じ。

## 5. 全部に共通する決まり

### 出力を変えていないことを機械で示す

このリポジトリでは、**同じフレームのPNGを `cmp` でバイト比較**して見た目が
変わっていないことを示す。既存に手を入れるときは必ずやる。

```sh
pnpm exec remotion still <Id> before.png --frame=420 --gl=swangle
# ...変更...
pnpm exec remotion still <Id> after.png --frame=420 --gl=swangle
cmp before.png after.png
```

- **レンダーの前後でソースの `md5` を取る。** 実行中に書き換えて偽の差分を出したことがある
- **各工程の中間フレームを撮る**（60, 180, 300, 420, 540, 660, 780）
- **既定のプリセットに含まれない分岐も撮る**（`--props` を渡せる）

### 既存に手を入れるときの作法

**既定値で従来どおりになるフラグを足す。** 既存の呼び出しを書き換えない。
`hidePanel` / `inactiveDashed` / `frameOverride` がその形になっている。

### デザインリストを作り直す

**`AgentFlow` にコンポジションを足したら、同じ変更のなかで作り直す。**

```sh
pnpm gallery:agent-flow
```

一覧は `src/Root.tsx` を読むので、**登録しただけでは載らない**。
忘れると `pnpm test:gallery` が落ちる。

### テスト

```sh
pnpm test            # 25件。gallery / inquiry-routes / side-studies / video
```

既存のテストは**実際のコンポジションを `react-dom/server` で描画して**
文字列を検査している（`useCurrentFrame` を差し替えるのでブラウザは要らない）。
新しい不変条件を守らせたいときは、この作り方が使える。
`scripts/side-studies.test.cjs` が短い実例。

### 動画に書き出す

```sh
pnpm video <Id>              # 1本
pnpm video <Id> --speed=2    # 2倍速（コマは間引かない）
```

必要なフラグは埋め込んであるので、素の `remotion render` は使わなくてよい。

## 6. 言い回しの約束（破ると商材が嘘になる）

- **AIの値を上書きする演出を作らない。** 実装が「書き換えない」設計なので、
  2つの値を並べて片方に印を付ける
- **実測でない数字には断りを付ける。** 47秒はシナリオ値。画面に明記する
- **通らない経路を消さない。** 未実装も、条件が合わないものも破線で残す
- **決定論のルールに色相を与えない**（白）。AIでも人でもない第3の主体
- **架空の実績を作らない。** 降格は「人だけができる・理由必須」という権限の説明に留め、
  降格した実績は描かない
