# [3] ワンページの型

[2]（[`agent-flow-diagram-patterns.md`](./agent-flow-diagram-patterns.md)）で作った図に、
何かを添えて1枚の資料にするまで。手順そのものは
[`presentation-production-playbook.md`](./presentation-production-playbook.md)、
実物の索引は [`presentation-site-variants.md`](./presentation-site-variants.md)。

ここは**型のカタログ**。用途に対してどの型を選ぶかを決めるための文書。

---

## 0. 入力

[2] の引き渡し票。特に **§2「この図が語れないこと」**が本体。
**添えるものは、この表の行から1つずつ立てる。** 思いつきで足さない。

図は4版（Cards / LogoSeal / IconsV2 / ActionRow）が揃っている前提。用途で選ぶ。

| 置き方 | 使う版 |
|---|---|
| 単体で読ませる・設計資料 | Cards |
| 1枚に埋め込んで縮小する | **ActionRow**（文字が少なく潰れにくい） |
| 地図まで小さくする | LogoSeal（形だけで読める） |
| 外部サービスとの接続を言う | IconsV2 |

---

## 1. まず用途を決める

同じ図でも、用途が違えば型が変わる。

| 用途 | 見る人の状態 | 効く型 |
|---|---|---|
| **展示会**（立って、音声なし、10秒） | 通りすがり。説明者がいない | D. 文字主体 |
| **商談**（座って、説明者つき、数分） | 質問してくる | A. 俯瞰＋現場 / C. 下段の帯 |
| **設計資料**（あとで一人で読む） | 細部を確かめたい | E. 図単体＋注記 |
| **社内共有**（読み手が前提を知らない） | 文脈がない | D → A の順で2枚 |

**1枚で全用途は無理。** 今回も展示会向けと商談向けで別物になった。

## 2. 型のカタログ

### A. 俯瞰＋現場（左右）

図を縮めて左、そのとき**実際に出ている画面**を右。

```
┌──────────────┐ ┌────────┐
│  フロー図      │ │ 現場    │
│ （0.59倍）     │ │ スマホ   │
│               │ │ JSON    │
└──────────────┘ │ 管理画面 │
                 └────────┘
```

- **効くこと**: 抽象が現物になる。「AIがP2と言った」は抽象だが、
  JSONに `"P2"` と書いてあるのを見せると現実になる
- **代償**: 情報量が多く視線が散る。**主役をどちらにするか先に決める**
- **要る素材**: [1] の票 §6（具体シナリオの値）。これが現場の中身になる
- **注意**: 図が既に同じ値を言っているなら外す（[2] §7 の `hidePanel`）

### B. 主役＋地図

一方を大きく、もう一方を「いまどこか」だけ示す地図まで小さくする。

- **効くこと**: 1920×1080 に2枚入れると**両方が読める大きさには収まらない**。
  諦めて役割を分けると成立する
- **実測**: 図は 0.26 倍まで落としても、光っている位置は分かる
- **使いどころ**: 文字主体の版（D）に経路を足したいとき

### C. 下段の帯

本体の下に、横長の帯を1本足す。**縦に積める余地は1帯ぶんしかない**ので、
ここに置けるのは1つだけ。候補は3つ。

| 帯 | 言えること | 向く用途 |
|---|---|---|
| **反実仮想** | 「その仕組みが無かったら」の結末 | **商談。芯が「担保」ならこれが最強** |
| **時間軸のログ** | 消えないこと ＋ 速さ ＋ 待ち時間の在処 | 記録が主張のとき |
| 凡例・注記 | 読み方 | 設計資料 |

反実仮想の作り: 2本並べ、**片方は仮定と明示**し、条件が満たされる工程から
片方だけ点灯させる。それまでは両方中立。

### D. 文字主体（図なし）

図をやめて、判断が積まれる様子を大きな文字で見せる。

- **効くこと**: **遠くからでも読める。**1文が刺さる
- **代償**: どこからどこへ流れているか語れない。B で地図を足すと補える
- **作り**: 工程ごとに見出し1つ・主張1つ。
  **値の欄を2つ並べて、片方が消えないことを形で示す**のが要

### E. 図単体＋注記

図をそのまま、余白に前提と限界を書く。設計資料向け。

- 実装のどこを見て描いたか、何を描いていないかを明記する
- **[1] の票をそのまま付録にする**のが一番早い

---

## 3. 選び方

```
芯が「担保」（間違えたときどうする）
  → 商談: A + C(反実仮想)
  → 展示会: D

芯が「速さ」
  → C(時間軸のログ)。待ち時間の在処が見えると強い

芯が「痕跡が残ること」
  → C(時間軸のログ) か D の値2欄

読み手が前提を知らない
  → D を先に1枚、A を2枚目

あとで一人で読む
  → E
```

## 4. 場所の予算

**早めに実測する。** 今回の値。

| | 実測 |
|---|---|
| 1920×1080 を左右2カラムに割ったとき、縦に積める余地 | **下に1帯ぶんだけ**（約110〜150px） |
| フロー図を左に置いたときの読める下限 | **0.59倍**でノード名が読める |
| 地図として許容できる下限 | **0.26倍** |
| 1920×1080 の作りものを2枚入れる | **両方が読める大きさには収まらない**。B に倒す |
| 右カラムの幅 | 590px で JSON・スマホ画面は入る。CSVの長い1行は要フォント調整 |

---

## 5. 重複を潰す

要素を足すと**同じことを複数の場所で言い始める**。今回は「47秒」が
時計・現場の出口・反実仮想の3箇所に出た。

1. **表示の重複**は、出す側ではなくレイアウト側で判断する。
   「時計を出しているなら出口では言わない」を画面に持たせると、
   画面がヘッダの事情を知ることになる
2. **値の重複**は、事実を1箇所に集めて構造で防ぐ。
   経過秒は最後のイベントから引く形にすれば、2箇所に書きようがない

**足すたびに「既にどこかで言っていないか」を確認する工程を挟む。**

## 6. 実装の型

### 既存の図を縮めて埋める

```tsx
<div style={{ width: 1920, height: 1080, transform: `scale(${s})`, transformOrigin: "top left" }}>
  <既存のコンポジション />
</div>
```

図が `useCurrentFrame()` だけで状態を決めていれば（[2] §5）、
**同期のコードは1行も要らない。** 縮小して置くだけで進行が揃う。
「図＋何か」の構成が驚くほど安く作れるのはこれのおかげ。

### 案は消さずに足す

既存のコンポジションを変えず、**別コンポジションとして足す**。
`zod` スキーマ＋プリセットにしておくと、Studio の props パネルから
登録していない組み合わせも試せる。

### 変えていないことを機械で示す

同じフレームのPNGを `cmp` でバイト比較する。運用上の注意3つ。

- レンダーの前後でソースの `md5` を取る（実行中に書き換えて偽の差分を出したことがある）
- 各工程の中間フレームを撮る（60, 180, 300, 420, 540, 660, 780）
- **既定のプリセットに含まれない分岐も撮る**（`--props` を渡す）

---

## 7. できたかどうかの検算

| 検算 | |
|---|---|
| 足した要素は「語れないこと」のどれかを埋めているか | 埋めていないなら外す |
| 同じ数字・同じ主張が2箇所に出ていないか | 出ていたら片方を消す |
| 主役が決まっているか | 両方大きいと必ず破綻する |
| 実測でない数字に断りがあるか | 画面に書く |
| 用途に合っているか | 展示会の資料を商談で使い回さない |
