## この題材を選ぶときに引っかかったこと

洗い出しの10件（[`agent-flow-research-example.md`](./agent-flow-research-example.md)）に
この業務は入っていない。**提案は「攻め」の業務で、一見すると
「間違いのコストが非対称」に当てはまらない**ように見えるため。

判定表（[`agent-flow-discovery.md`](./agent-flow-discovery.md) §3）を当て直すと、通る。

- **おとり広告は処分の対象**。成約済みの物件を出し続ける、条件を偽るなど。
  一方、提案しなかったことのコストは機会損失にとどまる。**非対称は成立する**
- 明文のルールが**列挙の形で存在する**（表示規約の必要な表示事項、徒歩1分=80m）
- **AIの出力を覆せる主体がいる**: 在庫の現況と表示規約。
  AIが「この物件がぴったり」と言っても、**成約済みなら出せない**

つまり芯は「良い物件を薦める」ではなく、**「薦めてよい物件か」**の側にある。

## [1]→[2] 引き渡し票

### 1. 芯

> **AIが薦めた物件を、そのまま候補者に出してよいのか。**

### 2. 主体と権限

| 主体 | 決められること | 決められないこと |
|---|---|---|
| 候補者 | 希望（自由文・口頭） | — |
| **AI** | 希望の構造化、候補の抽出と適合度の順位 | **出せるかどうか。順位を最終決定すること** |
| **表示規約と在庫の現況** | **出せない候補を落とす**（成約済み・必須表示が欠ける・徒歩分数が不整合） | 候補を足すこと |
| 審査基準 | 通過見込みで落とす（保証会社の基準） | 候補を足すこと |
| 営業担当 | **落とした候補を復活させる**のは根拠つきで可。提案の確定 | 規約違反の候補を出すこと |
| 提案記録 | — | （追記のみ） |

**AIの出力を覆せる主体**: 表示規約と在庫の現況。

### 3. 工程（7つ）

| # | 工程 | 何が増えるか |
|---|---|---|
| 1 | 相談受付 | 自由文・音声の希望が入る |
| 2 | 希望の構造化（AI） | エリア・予算・入居時期・譲れない条件に分解 |
| 3 | 候補の抽出（AI） | 適合度つきの候補リスト（**生出力**） |
| 4 | **在庫と表示規約で落とす** | 出せない候補と、その理由 |
| 5 | 審査の通過見込みで落とす | 見込みの薄い候補と、その理由 |
| 6 | 営業担当の確定 | 出す／出さないの決定。復活させるなら根拠 |
| 7 | 提案と記録 | 候補者に渡る一覧と、落とした理由の記録 |

**落とした理由を必ず残す**のがこの図の肝。提案は「出したもの」だけ見えるが、
**出さなかった判断のほうが説明責任を負う**。

### 4. 記録されるもの

- AIの候補リストの生出力（適合度つき・確定版と別に残す）
- 落とした候補と、落とした根拠（規約の条項／現況／審査基準）
- 担当者が復活させた場合の理由
- 提案履歴（追記のみ）

### 5. 通らない経路

- **成約済み物件の再掲載**（おとり広告。経路として描いて、止まっていることを見せる）
- **必須表示事項が欠けたままの掲載**
- **徒歩分数の実測と表示の不整合**（1分=80mの端数切り上げ）

### 6. 1件の具体シナリオ

- 入力（自由文）: 「3月から住みたいです。管理費込みで9万くらいまで。
  駅から歩いて10分以内がいいです。猫を1匹飼っています」
- **AIの構造化**: `{"入居":"2026-03","上限":90000,"徒歩":10,"ペット":"猫1"}`
- **AIの候補**: 5件（適合度順）
- **規約と現況で落ちる**: 2件（1件は成約済み、1件は徒歩表示が実測と不整合）
- **審査見込みで落ちる**: 1件（保証会社の基準に対し家賃が高い）
- **確定**: 2件を提案。担当者が1件を根拠つきで復活させ、計3件
- 所要: 相談から提案まで **当日中**（※シナリオ値）

### 7. 出典

- 不動産の表示に関する公正競争規約・同施行規則
  [規約全文PDF](https://www.sfkoutori.or.jp/webkanri/kanri/wp-content/uploads/2019/01/kiyak_zenbun.pdf) /
  [不動産公正取引協議会連合会](https://www.rftc.jp/koseikyosokiyaku/)
- 徒歩1分=80m（端数切り上げ）、必要な表示事項は別表で物件種別ごとに列挙
- 実装は無い。**構想**

## [2] 図の設計

### 3枚目としての位置づけ

ルールの形が3枚で揃う（[`agent-flow-research-domains.md`](./agent-flow-research-domains.md) 末尾）。

| 図 | ルールの形 | ルールの向き |
|---|---|---|
| ClaimIntake | 数値の閾値 | 緊急度を**上げる**だけ |
| Restoration | 定義＋数値表 | 借主負担を**下げる**だけ |
| **Proposal** | **列挙（必要な表示事項）** | 候補を**落とす**だけ |

**どれもルールは一方向にしか効かない。** 3枚並べるとそれが主張になる。

### 骨格

候補の「数が減っていく」ことを図で見せたいので、
ROW_1 を左から右への漏斗にする。

```
┌─ 外側 ─┬───────── ランタイム枠 ─────────┐  ┌ 記録層 ┐
│ ▢ 候補者 │ ROW_1 受付→構造化→抽出→規約→審査 │  │ ▭ 相談  │
│         │        5件      3件    2件        │  │ ▭ 候補  │
│         │ ROW_2 （落ちた候補と理由）         │  │ ▭ 除外理由│
└─────────┴────────────────────────────────┘  │ ▭ 提案  │
              ▢ 営業担当     ▢ 提案一覧        └────────┘
```

**ROW_2 に「落ちた候補」を置く**のが他の2枚と違うところ。
消えるのではなく下に落ちて残る、という見せ方にする。

### 色

| 主体 | 色 |
|---|---|
| 候補者・相談 | シアン |
| AIの抽出 | 紫 |
| **表示規約・現況** | **白** |
| 審査基準 | 白（同じく決定論） |
| 営業担当 | オレンジ |
| 提案・記録 | 緑 |

### 山場のパネル

候補の数の推移を出す。**落ちた理由が読めることが主張。**

```
AI（生出力）   5件   適合度順・そのまま残る
規約と現況    −2件   成約済み / 徒歩表示の不整合
審査見込み    −1件   保証会社の基準
担当者        +1件   「内見済みで本人が希望」← 理由が要る
確定          3件
```

## 決定と、残っている前提

- **在庫の入力元**（決定）: 自社基幹・レインズ・ポータル連携の**3つとも受ける**。
  どれか1つを選ぶのではなく、3ノードから「規約と現況」へ束ねて入る形にした
- **落とした理由の記録**（決定）: 記録まで含める。`exclusions` を記録層に立て、
  「落ちた候補」ノードを枠の中に残すことで、消えないことを図の形で示す

残っているもの。

1. **審査の通過見込みを機械で出しているか。** 出していないなら、
   この工程は「担当者の勘」になり、決定論のルールとして立てられない
3. **落とした理由を実際に記録しているか。** 記録していないなら、
   この図は「そうすべき」という提案になる。構想と明記する必要がある
4. **担当者が候補を復活させる場面があるか。** 無いなら権限の非対称が薄くなり、
   Restoration と同じ構図（人は増やす側）が作れない
